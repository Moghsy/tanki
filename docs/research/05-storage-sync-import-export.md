## 0. Architecture facts that shape everything else

1. **Two API layers exist in rslib.**
   - `anki::collection::{Collection, CollectionBuilder}` plus public `impl Collection` methods (e.g. `import_apkg`, `export_apkg`, `normal_sync`, `set_schema_modified`, `maybe_backup`). Many things are `pub(crate)` (e.g. `check_database`, `get_backup_limits`, `get_collection_timestamps`), so they are only reachable through layer 2.
   - `anki::backend::Backend` + the generated service traits in `anki::services` (`include!(OUT_DIR/backend.rs)`, `rslib/src/services.rs:9`). `Backend::new(tr: I18n, server: bool)` (`rslib/src/backend/mod.rs:83`) owns the open `Collection` behind a `Mutex<Option<Collection>>`, the tokio runtime (`runtime_handle`, 1 worker thread, mod.rs:130), the reqwest `Client` (`web_client`, http1 only, mod.rs:176), the sync abort handles, the background backup thread and the background media-sync thread. `Backend::run_service_method(service, method, bytes)` is generated by `rslib/rust_interface.rs:141`. **Anything touching sync, media sync, backups, colpkg import/export, custom TLS certs and AddMediaFromUrl exists only as Backend methods** (`BackendSyncService`, `BackendCollectionService`, `BackendImportExportService`, `BackendMediaService`, `BackendAnkiwebService`, `BackendGithubService`, `BackendAnkiHubService`).
   - Recommendation: tanki drives rslib through `Backend` (identical to what pylib does via `pylib/rsbridge`), because it gets Anki's exact locking/abort/progress semantics for free. Direct `Collection` calls are fine for pure collection ops.
2. **Progress is a single polled slot, not a callback.** `ProgressState { want_abort: bool, last_progress: Option<Progress> }` (`rslib/src/progress.rs:121`) is shared via `Arc<Mutex<..>>`. The GUI polls `Backend::latest_progress()` (`BackendCollectionService::latest_progress`, backend/collection.rs:85) every 100-150 ms (qt/aqt/sync.py:99-104, aqt/dbcheck.py:30-33). Only one operation's progress is visible at a time. Abort = `set_wants_abort()` (backend/collection.rs:90) for collection-scoped ops, `abort_sync()` / `abort_media_sync()` for network ops. `mod progress;` is private in `lib.rs`, so tanki reads progress via the `Progress` proto (`proto/anki/collection.proto:111-148`: `oneof value { media_sync, media_check, full_sync{transferred,total}, normal_sync{stage,added,removed}, database_check{stage,stage_total,stage_current}, importing, exporting, compute_*, download_update }`).
3. **Background Rust jobs are not awaited at process exit.** aqt calls `backend.await_backup_completion()` explicitly in `cleanupAndExit` (qt/aqt/main.py:609, comment "Rust background jobs are not awaited implicitly"). A short-lived `tanki <cmd>` process must do the same or an in-flight backup thread is killed mid-write. `close_collection` itself aborts and joins media sync (`abort_media_sync_and_wait`, backend/collection.rs:41).
4. **The Python layer is thin for data/sync/import/export**: almost all logic is in rslib. What Python adds is (a) profile/prefs management (`aqt/profiles.py`), (b) UI flows and confirmations, (c) LaTeX rendering (`pylib/anki/latex.py`), (d) Mnemosyne import (`pylib/anki/foreign_data/mnemosyne.py`), (e) paste/clipboard handling in the editor (mostly TS: `ts/routes/editor/rich-text-input/data-transfer.ts`), (f) add-on manager.

### 1.3 `prefs21.db` format

- SQLite file, **journal_mode=delete** [verified], one table: `CREATE TABLE profiles (name text primary key collate nocase, data blob not null)` (profiles.py:412-416). Opened with plain `anki.db.DB`, so it has none of the collection's custom collations - it is safe to read with any SQLite.
- Legacy: `prefs.db` is copied to `prefs21.db` if only the old file exists (profiles.py:388-391).
- Integrity: on open `pragma integrity_check`; on failure **both files are deleted** and recreated (profiles.py:395-427) - i.e. Anki loses all prefs (sync login etc.) rather than refusing to start.
- One row per profile (`name` = profile name, case-insensitive) plus one special row `name = '_global'`.
- `data` is a **Python pickle, protocol 4** [verified: bytes start `80 04`] of a plain `dict`. Written with `pickle.dumps(obj, protocol=4)` after converting top-level `QByteArray` values to `bytes` (profiles.py:205-210). Read with a custom `Unpickler(errors="ignore")` that special-cases `sip` types (profiles.py:174-203).
- `save()` (profiles.py:235-239) rewrites **both** the current profile row and `_global` from the in-memory dicts and commits. So Anki, when it exits or saves, overwrites whatever another program wrote (see 1.5/1.6).
- Defaults when a key is missing: code uses `profile.get(key, default)`; `profileConf` (profiles.py:92-109) only lists keys that "Anki 2.1.42 and below expect to exist".

**Value types seen** [verified by unpickling a copy with stub classes]: `str`, `int`, `bool`, `None`, `list[str]`, `dict[int,str]`, `dict`, `bytes` (Qt geometry/state blobs, 31-151 bytes). **Enum-typed values are pickled as class references** (`STACK_GLOBAL aqt.toolbar HideMode` + `REDUCE` with the int) [verified with `pickletools.dis`]. This happens for `top_bar_hide_mode`, `bottom_bar_hide_mode` (`HideMode`, toolbar.py:20) and `widget_style` (`WidgetStyle`, theme.py:48) in `_global`, if the user ever changed them. `theme` is stored as a plain int, `browser_layout` as a plain str.

### 1.4 Should tanki read/write prefs21.db?

Facts about reading from Rust:
- The container is trivial SQLite (`rusqlite` is already a dependency of `anki`). The only hard part is the pickle.
- Crate `serde-pickle` can decode protocol 4 dicts of `str/int/bool/None/list/dict/bytes` into its generic `Value`. **[unverified]** but very likely: it does NOT resolve arbitrary Python globals, so the enum case (`aqt.toolbar.HideMode` + REDUCE) and any legacy `sip._unpickle_type` values (PyQt QByteArray from old Anki; profiles.py:177-198) would fail the whole dict. A robust reader must tolerate this: either use a pickle parser that returns opaque `Global`/`Reduce` nodes (e.g. `serde-pickle` with lenient options if available, or a ~150-line hand-rolled opcode reader), or fall back to "unreadable -> ignore".
- Writing is the dangerous half: you must round-trip every unknown key byte-exactly (including enum REDUCE nodes and bytes) or Anki will either crash its unpickler (`find_class` ImportError is caught and the profile is **reset to defaults**, profiles.py:215-233, "resetting corrupt profile") or silently lose Qt geometry. Anki also overwrites whole rows on its own `save()`.

**Recommendation (decision):**
- **tanki keeps its own config** (e.g. `$XDG_CONFIG_HOME/tanki/config.toml`): UI prefs, key bindings, sync settings, "base folder / profile to use".
- **Read-only, best-effort import from prefs21.db** for convenience: list profile names (`select name from profiles where name != '_global'`), `last_loaded_profile_name`, and per-profile `syncKey`, `syncUser`, `currentSyncUrl`, `customSyncUrl`, `autoSync`, `syncMedia`, `networkTimeout`, `autoSyncMediaMinutes`. Open the DB `?mode=ro` / `PRAGMA query_only`. On any decode error, degrade to "not logged in".
- **Never write prefs21.db.** If tanki logs in itself, store its own hkey in its own config (preferably OS keyring or 0600 file) and keep `syncUser`/endpoint beside it. Caveat **[unverified]**: whether AnkiWeb returns the same hkey for repeated logins of one account (if it does, sharing is harmless; if not, a tanki login might invalidate Anki's stored key, causing an auth prompt in Anki, `clear_sync_auth` in sync.py:70-71 handles that gracefully on Anki's side).
- Profile discovery fallback that does not need prefs21.db at all: any `base/*/collection.anki2` directory.

### 1.5 Locking and single-instance mechanics

- **No lock file.** Desktop Anki's "single instance" is a per-user `QLocalServer` named `anki<md5(username)>` (or `ANKI_SINGLE_INSTANCE_KEY` env), qt/aqt/__init__.py:329-410. A second GUI launch just messages the first. tanki is not a Qt app and does not participate; there is no OS-level "Anki is running" marker file to check.
- **The real mutual-exclusion is SQLite.** `open_or_create_collection_db` (`rslib/src/storage/sqlite.rs:52-90`):
  - `busy_timeout(0)` (line 62) - never waits;
  - `PRAGMA locking_mode = exclusive` (line 64) then `journal_mode = wal` (line 68).
  With WAL + exclusive locking the DB never creates a `-shm` file and holds the lock for the whole lifetime of the connection. **[verified]** with a Python repro in this environment: connection A (`locking_mode=exclusive`, `journal_mode=wal`) then connection B (`timeout=0`): `select count(*) from x` -> `database is locked`; `pragma journal_mode` -> `database is locked`; after A closes, `-wal` is removed and B reads fine.
  - Result: **a second process (Anki desktop or tanki) that tries to open the same `collection.anki2` fails immediately** with `AnkiError::DbError{kind: DbErrorKind::Locked}` (error/db.rs:26,49; message "Anki already open, or media currently syncing.", db.rs:103). tanki should map this to a clear "Anki desktop (or another tanki) has this profile open" message and optionally poll/wait.
  - Consequence for the "share a profile folder" question: **concurrent writes to the collection are prevented by SQLite itself**. Sequential use is fine: Anki and tanki can alternate on the same profile as long as one has fully closed (closing checkpoints the WAL and removes it on clean close).
- **Not protected by that lock** (the sharing risks):
  1. `collection.media/` and `collection.media.db2`: the media DB is a separate SQLite WAL DB with default (rusqlite, 5 s) busy timeout and no exclusive mode (`rslib/src/sync/media/database/client/mod.rs:218-235`), the folder is plain files. Both programs can add/delete media simultaneously. The media DB is effectively a cache of the folder: `ChangeTracker::register_changes` rescans by folder/file mtime (`media/mod.rs:173`), so divergence is self-healing at the next sync, but **two programs running media sync concurrently with the same account** is untested territory. Mitigation: tanki refuses to start media sync if it could not take the collection lock (media sync runs inside the Backend which requires an open collection anyway).
  2. `prefs21.db` (see 1.4): no cross-process protection against last-writer-wins.
  3. `.colpkg` restore/import: `import_colpkg` writes a temp file and `atomic_rename`s it over `collection.anki2` (`import_export/package/colpkg/import.rs:39-58`) without checking for another process. On Linux the rename succeeds even if Anki has the old inode open exclusively; Anki would keep writing to an unlinked inode and its data is lost; a stale `collection.anki2-wal` next to the replaced file could in theory be paired with the new DB **[unverified theory]**. tanki must (a) close its own collection, (b) open+close the target collection once to prove it can take the lock (that fails if Anki desktop has it), then (c) call import. aqt does steps a only, because the GUI already guards single-instance.
  4. File-level copies: `collection.anki2` alone is not a consistent snapshot while WAL is non-empty. Anki's own backup does `storage.checkpoint()` first and reads the file skipping SQLite's locked region (`maybe_backup`, backup.rs:28-47; `anki_io::read_locked_db_file`, rslib/io/src/lib.rs:185-209). tanki should only ever back up through `create_backup`, never by `cp`.
- **Version skew** (Anki desktop X vs tanki's rslib Y): `SCHEMA_MAX_VERSION = 18`, `SCHEMA_MIN_VERSION = 11` (`storage/upgrades/mod.rs:3-9`). Opening a file with ver > 18, or ver 12/13, yields `FileTooNew` (sqlite.rs:485-495). A collection at ver 11 is **upgraded in place to 18 on open** inside `begin exclusive` (sqlite.rs:505-538); there is no automatic pre-upgrade backup in rslib (Python's "Downgrade & Quit" button exists for this: `ProfileManager.downgrade`, profiles.py:329-346, via `close_collection(downgrade_to_schema11=True)`). Normal close never downgrades (`col.close(downgrade=False)`, main.py:737). Beyond schema number, newer rslib may write config keys / card `data` JSON that older desktop versions don't know; they are JSON blobs so older versions generally ignore them, **[unverified]**.

### 1.6 Safe-sharing rules for tanki (proposed)

1. Always go through rslib (`Backend`/`Collection`); never raw-write SQL (see 2.4).
2. Treat `Locked` on open as "Anki is running"; never retry destructively.
3. Before any destructive operation (full download, colpkg restore, Check Database, import with scheduling), force a backup into `<profile>/backups` exactly like aqt does (`mw.create_backup_now()`: sync.py:249, dbcheck.py:35, importing.py:79): `Backend::create_backup{backup_folder, force: true, wait_for_completion: true}`.
4. Call `await_backup_completion` before exiting the process.
5. Do not write prefs21.db. Do not touch `addons21/`.
6. If both programs are used, prefer "one at a time" and print a warning when `<profile>/collection.anki2-wal` exists and is non-empty without a lock holder (i.e. an unclean shutdown) - opening it replays the WAL, which is correct but surprising.

## 2. Collection schema (rslib: all of it)

Files: `rslib/src/storage/schema11.sql`, `storage/upgrades/{mod.rs,schema14_upgrade.sql,schema15_upgrade.sql,schema17_upgrade.sql,schema18_upgrade.sql,schema11_downgrade.sql,schema18_downgrade.sql}`, `storage/sqlite.rs`.

### 2.1 Tables at schema 18 (current)

Verified on a real collection [verified]: `col, notes, cards, revlog, deck_config, config, fields, templates, notetypes, decks, tags, graves, sqlite_stat1, sqlite_stat4`, `col.ver = 18`, `journal_mode = wal`, `page_size = 4096`.

- `col` (single row, id 1): `crt, mod, scm, ver, dty, usn, ls, conf, models, decks, dconf, tags`. At v18 `conf/models/decks/dconf/tags` are empty `{}` placeholders; real data moved to their own tables. `mod` = last collection change (ms), `scm` = last schema change (ms), `ls` = last sync (ms), `usn` = server usn.
- `notes(id, guid, mid, mod, usn, tags, flds, sfld integer, csum, flags, data)`; fields joined by `\x1f`.
- `cards(id, nid, did, ord, mod, usn, type, queue, due, ivl, factor, reps, lapses, left, odue, odid, flags, data)`; `data` is JSON (FSRS state, custom data).
- `revlog(id, cid, usn, ease, ivl, lastIvl, factor, time, type)`.
- `graves` v18: `(oid, type, usn, PRIMARY KEY(oid,type)) WITHOUT ROWID` + `idx_graves_pending(usn)` (schema18_upgrade.sql); v11 form `(usn, oid, type)`.
- v14: `deck_config(id, name COLLATE unicase, mtime_secs, usn, config blob)`, `config(KEY text PK, usn, mtime_secs, val blob JSON) WITHOUT ROWID`, `tags(tag text PK COLLATE unicase, usn) WITHOUT ROWID`.
- v15: `fields(ntid, ord, name COLLATE unicase, config blob)`, `templates(ntid, ord, name COLLATE unicase, mtime_secs, usn, config blob)`, `notetypes(id, name COLLATE unicase, mtime_secs, usn, config blob)`, `decks(id, name COLLATE unicase, mtime_secs, usn, common blob, kind blob)`, plus indexes (`idx_notetypes_name` unique, `idx_decks_name` unique, `idx_notes_mid`, `idx_cards_odid`, ...).
- Blobs in v14+ tables are **protobuf** (`prost`), not JSON; `config.val` is JSON.
- v16/v17 are data-only upgrades (deck conf and tag canonicalisation, `upgrade_deck_conf_to_schema16`, `upgrade_tags_to_schema17`).

### 2.2 Open (upgrade) and close (downgrade)

- `SqliteStorage::open_or_create(path, tr, server, check_integrity)` (sqlite.rs:476): creates the schema-11 tables from `schema11.sql` if `col` is missing then runs `upgrade_to_latest_schema` (upgrades/mod.rs:14-47) - **a brand-new collection is created as v11 and immediately upgraded to 18**, and gets default deck, deck config and stock notetypes. `check_integrity=true` runs `pragma integrity_check` (used for downloaded/uploaded files).
- `close(desired_version: Option<SchemaVersion>)` (sqlite.rs:549-559): `SchemaVersion::{V11, V18}`; V11 runs the downgrade scripts (drops the new tables, restores `col.models/decks/dconf/conf/tags` JSON) in one transaction, then `journal_mode = delete`. V18 is a no-op. Backend exposes it as `CloseCollectionRequest.downgrade_to_schema11` (collection.proto:51-53).
- Full upload closes with `Some(SchemaVersion::V18)` (sync/collection/upload.rs:46) (modern servers take v18). Legacy `.colpkg`/`.apkg` export with `legacy=true` downgrades to v11 (colpkg/export.rs:62-66; meta.rs:33-41).
- WAL checkpoint for safe file copy: `SqliteStorage::checkpoint()` (sqlite.rs:561-583, `pragma wal_checkpoint(truncate)`).
- Optimise: `SqliteStorage::optimize()` = `vacuum; reindex; analyze` (sqlite.rs:642) is only reachable through Check Database; aqt's 14-day auto-optimise is Python SQL `vacuum` + `analyze` via the DB proxy (`pylib/anki/collection.py:1125`, main.py:754). tanki must do its own `select`-free equivalent through `Backend::run_db_command_bytes` (the same path the Python DBProxy uses, backend/mod.rs:105) or just rely on Check Database.

### 2.3 Custom SQL functions and collations (why raw access is hazardous)

Registered per connection in `open_or_create_collection_db` (sqlite.rs:76-87): scalar functions `field_at_index`, `regexp`, `regexp_fields`, `regexp_tags`, `process_text`, `fnvhash`, `extract_original_position`, `extract_custom_data`, `extract_fsrs_variable`, `extract_fsrs_retrievability`, `extract_fsrs_relative_retrievability`, and collation **`unicase`** (`UniCase` comparison, sqlite.rs:37-39,87).

**[verified]** on a copy of a real v18 collection with stock Python `sqlite3`:
- `select count(*) from decks order by name` -> `no such collation sequence: unicase`
- `insert into tags(tag,usn) values('x',0)` -> `no such collation sequence: unicase`
- `select * from tags where tag='x'` -> `no query solution`
- `select ver from col` and plain counts on `notes/cards/revlog` work.

So: external tools (sqlite3 CLI, DB Browser, Python scripts, any other crate without registering `unicase`) can read `col/notes/cards/revlog` but fail or, worse, mis-order/mis-write on `decks`, `notetypes`, `tags`, `fields`, `templates`, `deck_config` and corrupt the unique indexes if they bypass the collation. Writes that don't set `mod`/`usn` also break sync invariants. tanki rule: **only rslib touches the collection file**; if tanki wants ad-hoc SQL it uses `Collection.storage.db()` (public escape hatch, sqlite.rs:93-98, connection already has the functions) and for writes must also bump `mod` (`Collection::set_modified()` is `pub`, collection/timestamps.rs:25).

### 2.4 Schema-modified ("this change requires a full sync") plumbing

- `col.scm` vs `col.ls`: a schema change newer than last sync forces a one-way (full) sync. Rust sets it (`Collection::set_schema_modified()` is `pub`, collection/timestamps.rs:36) in: notetype field/template/sort-field changes (notetype/schemachange.rs:79,101,134), notetype removal (notetype/mod.rs:800), change-notetype (notetypechange.rs:222), deck-config removal (deckconfig/mod.rs:219), scheduler version upgrade (scheduler/upgrade.rs:126), Check Database repairs (dbcheck.rs:184,193,226,328,424,448), colpkg import (colpkg/import.rs:68), failed sanity check (sync/collection/normal.rs:109), and the CollectionBuilder (collection/mod.rs:203).
- **rslib does not ask for confirmation.** The confirm dialog is Python-only: `Collection.mod_schema(check)` (pylib/anki/collection.py:312-317) fires `hooks.schema_will_change` -> `AnkiQt.onSchemaMod` -> `confirm_schema_modification()` (main.py:1701-1707, text `qt_misc_the_requested_change_will_require_a`), used by deck delete (decks.py:352), notetype delete (models.py:431), deck-config removal (deckconf.py:145; deckbrowser.py:433), change-notetype (changenotetype.py:72), and the card layout/fields editors through `ChangeTracker` (qt/aqt/schema_change_tracker.py, `mark_schema()`).
- Detect "schema already changed since last sync" without confirmation: Python does `select scm > ls from col` (collection.py:319-321); in tanki use `Collection::sync_status_offline()` (pub, sync/collection/status.rs:16) -> `Required::FullSync`, or the same SQL through `storage.db()`.
- **tanki requirement:** before invoking any of the operations listed above, check `scm > ls` and, if the user has ever synced (`ls != 0`), prompt (TUI modal) or require `--yes`/`--force-schema-change` on the CLI; otherwise the user is silently forced into an upload/download choice next sync. **[Re-implement UI; trivial/doable.]**
- Forcing a full sync deliberately (Preferences "force full sync"): `mod_schema(check=False)` = `update col set scm=<now ms>` (preferences.py:323-324).

### 3.2 Endpoints, redirects, self-hosted servers

- Default endpoint `https://sync.ankiweb.net/` (`HttpSyncClient::new`, sync/http_client/mod.rs:45) when `SyncAuth.endpoint` is None. URLs are `<base>/sync/<method>` (`SyncMethod::{HostKey, Meta, Start, ApplyGraves, ApplyChanges, Chunk, ApplyChunk, SanityCheck2, Finish, Abort, Upload, Download}`, collection/protocol.rs:35-58) and `<base>/msync/...` for media.
- **hostNum is dead**: sync version 11 (`SYNC_VERSION_MAX`, sync/version.rs:12,36-39) "hostNum has been deprecated in favour of a redirect". The server answers `/sync/meta` with HTTP 308 `PERMANENT_REDIRECT` and the new base URL in the body; the client retries and returns it as `new_endpoint` (sync/collection/meta.rs:95-117). **The caller must persist `new_endpoint`** (aqt: `set_current_sync_url`, sync.py:56-57,117-118); otherwise it re-discovers every time.
- Endpoint precedence in aqt: `currentSyncUrl or customSyncUrl or None` (profiles.py:696-697). Changing `customSyncUrl` wipes `currentSyncUrl`. Endpoint strings are normalised with `Url::try_from(v).and_then(|x| x.join("./"))` (backend/sync.rs:82-92) so `host:8000` style input errors cleanly ("Invalid sync server specified").
- AnkiWeb-specific rules keyed off the substring `"ankiweb"` in the endpoint: upload limit check `MAXIMUM_SYNC_PAYLOAD_BYTES_UNCOMPRESSED` = 3 x `MAX_SYNC_PAYLOAD_MEGS` (default 100 MB) = **300 MB** collection size (sync/request/mod.rs:180-191; normal.rs:74-79; upload.rs:50-55 -> `SyncErrorKind::UploadTooLarge`). Not enforced for custom servers.
- Client identification: `"anki,<version> (<buildhash>),<platform>"` where platform = env `PLATFORM` else `std::env::consts::OS` (rslib/src/version.rs:14-26); aqt sets `os.environ["PLATFORM"] = plat_desc()` (sync.py:409). A tanki build will otherwise advertise itself as "anki,26.08.1 (dev),linux". Decide deliberately whether to set `PLATFORM=tanki`. **[unverified]** whether AnkiWeb rejects unknown platform strings; the version string is what matters for compatibility gating.
- Clock check: |server time - local time| > 300 s -> `SyncErrorKind::ClockIncorrect` (status.rs:56-60). Needs an NTP-ish hint in the TUI.
- `Meta` also carries `should_continue`/`server_message`: if the server says stop, `SyncErrorKind::ServerMessage` with the text (status.rs:49-55). Non-fatal server messages are returned in `SyncCollectionResponse.server_message` and aqt shows them as rich text (sync.py:119-120). tanki must print them.

### 3.3 HTTP client and TLS

- `reqwest 0.12.20` with `default-features = false, features = [json, socks, stream, multipart]` (workspace Cargo.toml:115). TLS is **opt-in** via crate features on `anki`: `rustls = ["reqwest/rustls-tls", "reqwest/rustls-tls-native-roots"]` or `native-tls = ["reqwest/native-tls"]` (rslib/Cargo.toml:13-15). The sync server binary picks rustls everywhere except Windows (rslib/sync/Cargo.toml:17-21); pylib's `rsbridge` exposes the same two features. **tanki must enable exactly one of them** (recommend `rustls` for static Linux builds), otherwise `https://` endpoints cannot work **[unverified at runtime, strongly implied by the feature layout]**.
- Client: `Client::builder().http1_only().build()` (backend/mod.rs:176-183; "nginx doesn't support http2 proxies"). System proxy env vars are honoured by reqwest defaults; SOCKS via the `socks` feature.
- Requests are zstd-compressed bodies with a JSON `SyncHeader` header (`anki-sync`), `IoMonitor` provides per-request read/write timeouts = `io_timeout_secs` (default 30 s in Rust, 60 in aqt), and byte counters for full-sync progress (sync/http_client/io_monitor.rs, full_sync.rs:21-55).

Note: **aqt never calls it** (grep over qt/ and pylib/ finds no use), so desktop Anki cannot use self-signed servers but tanki could expose `tanki config set sync.ca-cert FILE`. **[doable, free win]**

### 3.4 The normal sync flow (what a CLI must orchestrate)

aqt flow (qt/aqt/sync.py, main.py:1091-1138):
1. `sync_auth = pm.sync_auth()`; if none -> login dialog -> `col.sync_login(username, password, endpoint)` -> `SyncAuth(hkey)`; store `syncKey`, `syncUser` (sync.py:307-346). Auth failures (`SyncErrorKind::AuthFailed` -> Python `SyncErrorKind.AUTH`) clear the stored key (sync.py:68-71 `clear_sync_auth` also wipes hostNum/currentSyncUrl).
2. `sync_collection(auth, sync_media)` runs in a background thread; 150 ms timer polls `latest_progress().normal_sync{stage,added,removed}` and calls `abort_sync()` on cancel (sync.py:78-135).
3. Inside rslib (`NormalSyncer::sync`, normal.rs:69-117): `sync_meta` -> size check -> `online_sync_status_check` (meta call with redirect handling) -> depending on `ClientSyncState.required`: `NoChanges` returns; `FullSyncRequired{upload_ok, download_ok}` returns to caller; `NormalSyncRequired` runs `discard_undo_and_study_queues`, `unbury_if_day_rolled_over`, **`begin_trx` (one exclusive transaction for the entire sync)**, then `start_and_process_deletions` (graves) -> `process_unchunked_changes` (notetypes/decks/tags/config) -> `process_chunks_from_server` -> `send_chunks_to_server` -> `sanity_check` -> `finalize` (normal.rs:121-143). On error: rollback, `abort` call to server, and **on `SanityCheckFailed` it calls `set_schema_modified()` so the next sync is forced full** (normal.rs:95-112). `SyncErrorKind::{Conflict, ServerError, ClientTooOld, AuthFailed, ServerMessage, ClockIncorrect, Other, ResyncRequired, DatabaseCheckRequired, SyncNotStarted, UploadTooLarge, SanityCheckFailed{client,server}}` (error/network.rs:35-51; HTTP 409->Conflict, 403->AuthFailed, 501->ClientTooOld, 5xx->ServerError, 400->DatabaseCheckRequired, error/network.rs:105-136). `SyncError::message(tr)` yields localised text.
4. Response handling: `host_number` (store, informational), `new_endpoint` (persist), `server_message` (display), `required`:
   - `NO_CHANGES` -> done; start media-sync *monitoring* (`media_syncer.start_monitoring()`; the backend already started the media sync thread because `sync_media=true`, backend/sync.rs:386-390).
   - `FULL_DOWNLOAD` / `FULL_UPLOAD` -> **confirmation prompt** (sync.py:172-202: "some users customize notetypes in an empty collection then want to upload"), then `full_download`/`full_upload`.
   - `FULL_SYNC` -> the **conflict dialog** "Upload to AnkiWeb / Download from AnkiWeb / Cancel" (default Cancel; text key `sync_conflict_explanation2`, sync.py:147-169).
5. Full sync details: before download aqt does `mw.create_backup_now()` (sync.py:249); for upload it does not. Then `col.close_for_full_sync()` and `full_upload_or_download(auth, server_usn, upload)`. In rslib `full_sync_inner` (backend/sync.rs:401-457): abort media sync and wait, take the collection out of the mutex, run upload/download (abortable), **always re-open the collection** (even on error), update cached status, and if OK and `server_usn` was provided start background media sync. Upload: `before_upload()` clears graves/pending usns (collection/mod.rs:190+), closes with `V18`, reads the whole file, size-checks, POSTs; server verifies by opening it with `check_integrity` and answers `"OK"` or `CORRUPT_MESSAGE` (upload.rs:31-102). Download: closes, GETs, writes temp file, opens with `check_integrity`, sets `ls = mod`, `atomic_rename` over the collection (download.rs:27-46). Progress: `FullSync{transferred,total}` bytes.
   - **Data-safety note for tanki:** full download replaces `collection.anki2` wholesale. Do `create_backup(force=true, wait=true)` first (aqt does) and require explicit confirmation.
6. After a full sync the Python side reloads scheduler (`mw.col._load_scheduler()`), models cache, queues, etc. tanki equivalent: drop all cached state and re-read decks/notetypes.

### 3.5 sync_status (the "sync button colour")

`SyncStatus(auth)` (backend/sync.rs:312-352): first `sync_status_offline()` (local only: `never_synced` -> NoChanges; `scm > ls` -> FullSync; `mod > ls` -> NormalSync); if local is clean, a **network meta call**, cached for **300 s** (`remote_sync_status`, sync.rs:322-330) and refreshed with a time-of-check guard (sync.rs:335-349). aqt calls it on a timer to colour the toolbar button (blue = normal, red = full) and swallows errors (sync.py:41-65; "docs-site/manual/syncing.mdx: Button Color"). **tanki:** show a status-bar indicator after `SyncStatus`; in CLI `tanki sync --status` (exit code 0 = clean, 10 = normal sync needed, 11 = full sync needed).

### 3.6 Media sync

- `Backend::sync_media_in_background` (backend/sync.rs:188-210): single background `std::thread` + abort handle; a second call while running is a no-op. Status is polled: `MediaSyncStatus -> {active, progress}`; **if the background task ended with an error, the next `MediaSyncStatus` call returns that error** (sync.rs:212-237). - Protocol (rslib/src/sync/media/syncer.rs:61-95): `register_changes` (scan folder, mtime-based) -> `begin` (server usn) unless `server_usn` was passed from the collection sync -> if local usn != server usn `fetch_changes` (batches; download in zips of <=25 files `MAX_MEDIA_FILES_IN_ZIP`; target 2.5 MiB per upload zip) -> `send_changes` (pending dirty entries) -> `finalize_sync` -> `media_sanity_check`; on mismatch `force_resync` + `SyncErrorKind::ResyncRequired`. Limits: file name <=120 bytes (`MAX_MEDIA_FILENAME_LENGTH`, sync/media/mod.rs:20), file <=100 MiB.

Errors during periodic syncs are only printed.
- Abort: `abort_media_sync()` (+ `set_wants_abort()`) (mediasync.py:114-119). `close_collection` aborts and waits.
- **tanki:** a CLI `tanki sync` must keep the process alive until `MediaSyncStatus.active == false` (poll at 250 ms like mediasync.py:48-55) *before* closing; a long-running TUI can run the periodic timer in-app. Because collection open + media sync run inside one `Backend`, tanki's TUI naturally gets background media sync.

### 3.7 Auto-sync on open/close

## 4. Media management (rslib except pasted-image decoding and LaTeX)

### 4.1 Adding files

- `Collection::media() -> Result<MediaManager>` (media/mod.rs:33); `MediaManager::add_file<'a>(&self, desired_name: &'a str, data: &[u8]) -> Result<Cow<'a, str>>` (mod.rs:66): SHA-1 of data, writes via `add_data_to_folder_uniquely`, inserts/updates the `media` row with `dirty=1` in the media DB inside a transaction that also keeps the folder-mtime marker in sync (mod.rs:112-130).
- RPCs (`proto/anki/media.proto`): `MediaService { CheckMedia, AddMediaFile{desired_name,data}->String, AddMediaFromPath{path}->String, TrashMediaFiles{fnames}, EmptyTrash, RestoreTrash, ExtractStaticMediaFiles(NotetypeId)->StringList, ExtractMediaFiles(String)->StringList, GetAbsoluteMediaPath(String)->String }` and `BackendMediaService { AddMediaFromUrl{url}->{optional filename, optional error} }` (backend/media.rs:12-39; **panics with `unwrap()` if no collection is open**, media.rs:18).
- Naming/dedup algorithm (`rslib/src/media/files.rs:94-209`, tests at ~493-535):
  1. `normalize_filename`: NFC; strip `[ ] < > : " / ? * ^ \ |`, ASCII control chars and Unicode-unassigned chars; NBSP -> space; Windows device names (`CON PRN AUX NUL COM1-9 LPT1-9`) get `_` after the stem; a trailing space or dot gets `_` appended; truncate to **120 bytes** keeping the extension (<=10 bytes) on a char boundary (`MAX_MEDIA_FILENAME_LENGTH = 120`).
  2. If a file with that exact name exists with the **same SHA-1**, reuse it (no write).
  3. If the name has uppercase, retry with `to_lowercase()` - **so new files are always stored lower-cased** (unless an identical-content file with the exact-case name already exists). Example from the test: adding `Test.mp3` with different content when `test.mp3` exists gives `test-<sha1hex>.mp3`.
  4. Same name, different content -> `stem-<40-hex sha1>.ext`.
  So **the returned name may differ from the requested one; callers must insert the returned name into the field.**
- `AddMediaFromUrl` -> `retrieve_url` (rslib/src/editor.rs:17-50): supports `http(s)`/`ftp` download and `file://`; filename from the URL path (query stripped, percent-decoded), `paste` if empty, extension added from Content-Type if missing (`add_extension_based_on_mime`; mime map image/{jpeg,png,svg+xml,webp,avif}, audio/{mpeg,ogg,opus,wav,webm,aac}). Errors come back in `error` rather than failing the RPC.
- Media DB (`collection.media.db2`) schema (`sync/media/database/client/schema.sql`): `media(fname PK, csum text, mtime int, dirty int) WITHOUT ROWID`, `meta(dirMod int, lastUsn int)`; it is a rebuildable cache.

### 4.2 Check Media (`CheckMedia`)

`media/check.rs`, service at media/service.rs:20-36 (runs inside `transact_no_undo`):
- Checks the folder: renames files with invalid names (NFC/forbidden chars), dedups names case-insensitively, notes subfolders (`dirs`) and files over 100 MiB (`oversize`), lists all files.
- Checks references: scans every note's fields for `<img src>`, `[sound:...]`, LaTeX-generated names (`latex-<hash>.png/svg`, `extract_latex_refs`, check.rs:602-609) and notetype template/CSS static media; **rewrites references to renamed files and extracts inline `data:` images into files (`maybe_extract_inline_image`, check.rs:534)** - i.e. the check is **not read-only** (it can modify notes). There is no dry-run mode.
- Output `CheckMediaResponse { repeated string unused, repeated string missing, repeated int64 missing_media_notes, string report, bool have_trash }` (media.proto:35-41). `report` is a human-readable localised text with sections (trash count/MB, missing N, unused N, extracted images, renamed files, oversize, subfolders, then file lists).
- Python-only follow-ups (qt/aqt/mediacheck.py): "Delete Unused" = `col.media.trash_files(chunk of 25)` with confirmation (mediacheck.py:190-222); "Empty Trash" / "Restore Trash" = `EmptyTrash`/`RestoreTrash` RPCs; **"Render LaTeX"** (only offered if any missing file starts with `latex-`) = Python `render_all_latex` (pylib/anki/media.py:184-218) which loops over notes containing `[`, calls the RPC `ExtractLatex` (rslib) and then shells out to `latex` + `dvipng` (or `dvisvgm` for svg notetypes) in a temp dir (pylib/anki/latex.py:20-45,121-170). To support it tanki needs: the extraction RPC (rslib, free), subprocess orchestration (trivial), and external TeX installation (user's problem). Respect `Config.Bool.RENDER_LATEX` (disables generation).
- Trash: files are moved to `<profile>/media.trash/` with mtime set to now (files.rs:340-372; no automatic expiry yet - comment says so); `restore_trash` moves back files that are not conflicting (check.rs:391-420); `empty_trash` deletes (check.rs:377-389). `MediaManager::remove_files` also marks the media DB row as deleted/dirty so the deletion syncs.

### 4.3 How the editor adds media (to re-implement for the TUI)

- Desktop editor is TS (`ts/routes/editor/rich-text-input/data-transfer.ts`), legacy Python editor in `qt/aqt/editor_legacy.py:893-1002`. Core rules:
  - Attach from file: `AddMediaFromPath` (basename -> `add_file`). Link HTML: image extensions (`jpg jpeg png gif svg webp ico avif`) -> `<img src="<urlencoded name>">`, otherwise `[sound:<name>]`.
  - Paste/drag of a URL: allowed suffix check, then `AddMediaFromUrl`.

There is **no resize** anywhere; the only paste image option is PNG vs JPEG.
  - `data:image/(jpg|jpeg|png|gif);base64,...` inline images are converted to `paste-<sha1>.<ext>` the same way (data-transfer.ts:227-241).
  - HTML cleanup on paste (`PASTE_STRIPS_FORMATTING`, `_pastePreFilter` with BeautifulSoup removing `script iframe object style`, editor_legacy.py:1056+) - editor feature.
- **tanki:** `tanki media add FILE...` and the TUI editor's "attach" command -> `AddMediaFromPath`; clipboard image paste via `wl-paste`/`xclip`/`pbpaste`-style helper + `image` crate re-encode (PNG q50 equivalent is not directly expressible: use `png` crate default/“fast” compression, JPEG q80) + `AddMediaFile`. Terminal limitation: inline image preview requires kitty/sixel/iterm protocols; fall back to filename.

### 4.4 Media sync protocol and change tracking in detail (addendum)

Source: `rslib/src/sync/media/{protocol,syncer,changes,download,upload,zip,sanity,begin}.rs`, `sync/media/database/client/{mod,changetracker}.rs`, `media/files.rs`.

- **Wire protocol** (`MediaSyncMethod`, sync/media/protocol.rs:26-41): POST `<base>/msync/{begin, mediaChanges, uploadChanges, downloadFiles, mediaSanity}`. Same zstd body + `SyncHeader` header as collection sync (sync v11 "stops using a separate session key for media syncs", sync/version.rs:25-27). Responses of four of the five calls are wrapped in `JsonResult<T>` = `{data, err}` (protocol.rs:67-101); a non-empty `err` becomes `AnkiError::server_message(err)` -> shown verbatim to the user. `begin` -> `{host_key, usn}` (`usn` is the server media USN); `mediaChanges{lastUsn}` -> list of `[fname, usn, sha1]` tuples (empty sha1 = deleted on server, changes.rs:19-26); `downloadFiles{files:[..]}` -> zip with `_meta` JSON map (zip-entry-name -> real file name); `uploadChanges` -> zip, reply `{processed, current_usn}`; `mediaSanity{local: count}` -> `ok`/mismatch.
- **Conflict rules** (`determine_required_change`, changes.rs:44+): server add wins over a local pending deletion; server deletion with a local *pending* (dirty) add is ignored and uploaded later; server deletion with clean local -> the local file is removed via `MediaManager::remove_files` (syncer.rs:146; media/mod.rs:92-108), which calls `files::remove_files` (files.rs:340-372) and therefore **moves it into `<profile>/media.trash/`** rather than unlinking it; media deleted by another device stays recoverable locally until the trash is emptied.
- **Downloaded names are re-normalised** (`add_file_from_ankiweb`, files.rs:395-435): a name that is already valid is written **directly, overwriting any existing file of that name** (server wins, no hash check); an invalid name (old AnkiWeb data) is renamed through `add_data_to_folder_uniquely` and reported as `renamed_from`. Because `/`, `\` etc. are stripped by `normalize_filename`, a malicious/odd server file name cannot escape the media folder (zip `_meta` lookup failure -> `SyncErrorKind::Other "malformed zip"`, download.rs:41-43).
- **Change detection = folder mtime gate + per-file mtime/sha1** (`ChangeTracker::register_changes`, changetracker.rs:56-80): if the media **folder's mtime equals the stored `meta.dirMod` the scan is skipped entirely** ("skip check"). Otherwise it lists the folder (`read_dir_files`; non-normalized names get renamed/skipped, `thumbs.db`/`.ds_store` ignored via `NONSYNCABLE_FILENAME`, files > `MAX_INDIVIDUAL_MEDIA_FILE_SIZE` = 100 MiB skipped), compares mtimes with the DB, hashes changed files and marks entries dirty/deleted. Consequences: (a) editing a file in place does not change the directory mtime, so it is not noticed until some add/remove/rename touches the folder (matches the manual); (b) `MediaManager::transact` (mod.rs:112-130) deliberately keeps `dirMod` in step with tanki's own `add_file`, so tanki-made additions are marked dirty without a rescan, and files added by Anki desktop or by hand are picked up on the next sync's `register_changes`. This is why sharing the media folder between desktop Anki and tanki is self-healing - as long as both use the same `collection.media.db2`.
- **Case/Unicode**: `Checksums::get` lower-cases keys to cope with case-insensitive filesystems (database/client/mod.rs:24-33); on Apple platforms an on-disk NFD name is accepted as NFC when otherwise valid (`filename_if_normalized`, files.rs:140-163). Linux/ext4 is case-sensitive, so a collection used on Linux+Mac can contain names differing only by case; Check Media dedups them case-insensitively (check.rs:256+).
- **Failure/abort behaviour**: abort -> `AnkiError::Interrupted` (backend/sync.rs:261-266); media DB updates are committed per batch (`db.transact`, syncer.rs:176-187, 237-251), so an interrupted sync resumes cleanly from `lastUsn`. A sanity mismatch calls `force_resync` (marks everything for re-evaluation) and returns `ResyncRequired` (syncer.rs:264-269) - tanki should auto-retry once, as the error text tells the user to sync again.
- **Server side** (for `tanki sync-server`): `sync/http_server/media_manager/` keeps its own `ServerMediaManager` DB (`schema_v3.sql`/`schema_v4.sql`) per user folder; max server-side name length is 255 (`MAX_MEDIA_FILENAME_LENGTH_SERVER`, sync/media/mod.rs:24).
- **tanki consequences**: (1) use the Backend's background media sync, not `MediaManager::sync_media` directly (its `ThrottlingProgressHandler` is awkward to build outside the crate, though `Collection::new_progress_handler` is `pub`, progress.rs:339); (2) after `sync_collection` returns, **do not exit/close until `MediaSyncStatus.active == false`**, and call `MediaSyncStatus` one last time because it is the only place a background error is surfaced (backend/sync.rs:212-237); (3) a CLI `tanki media sync` = `SyncMedia(auth)` + poll (the collection must be open; it is a no-op for "closed collection" use); (4) full-sync download does not touch media, so after a one-way sync the media DB and folder remain; the server USN returned by the collection sync (`server_media_usn`) lets media sync skip the `begin` round trip.

### 5.2 .apkg (package import)

- ZIP; `meta` entry = protobuf `PackageMetadata{version}` (`VERSION_LEGACY_1`: `collection.anki2`; `LEGACY_2`: `collection.anki21`; `LATEST`: zstd `collection.anki21b`); missing `meta` -> infer from file presence (package/meta.rs:71-95). Legacy files are plain, latest files are zstd-compressed (meta.rs:107-125). - Algorithm (`Context::import`, apkg/import/mod.rs:96-120): extract collection to tempfile -> `maybe_fix_invalid_ids`, `maybe_upgrade_scheduler` -> `prepare_media` -> `import_notes_and_notetypes` -> `import_decks_and_configs` -> `import_cards_and_revlog` -> `copy_media`; wrapped in `Op::Import` so it is **undoable**.

Result log categories: new/updated/duplicate/conflicting/(others unused for apkg).
- **Heads-up (Python behaviour to replicate):** aqt treats a file as a *full collection package* (replace collection!) if the name is `collection.apkg`, starts with `backup-` and ends `.apkg`, or ends in `.colpkg` (importing.py:35-41). tanki's CLI should instead decide by package content (`meta`/`collection.*` plus whether it is a full-collection export) or require explicit `tanki restore FILE` for destructive replace.

### 5.3 .colpkg (replace collection)

- Same ZIP container; `collection.anki21b` (zstd) or legacy `collection.anki21`/`anki2`. `import_colpkg` (colpkg/import.rs:31-61): extracts+decompresses into a temp file next to the target, `check_collection_and_mod_schema` (opens it, `set_schema_modified()` + `set_modified()`, `pragma integrity_check == "ok"`, else `ImportError::Corrupt`), restores media into `collection.media` (merge: existing identical files skipped by size/sha1 comparison; **does not delete extra media**), then `atomic_rename` over the live collection. ### 5.4 Text/CSV/TSV import

- Detection pipeline (`get_reader_metadata`, csv/metadata.rs:59-78): start from collection-stored defaults for dupe resolution and match scope (`I32ConfigKey::CsvDuplicateResolution`, `MatchScope`) -> parse **header lines** -> delimiter fallback -> preview (first 5 records, 80 chars/field, HTML stripped for display) -> html fallback -> columns -> notetype/deck defaults (`defaults_for_adding`) -> auto-map columns to fields by name (when a `#columns:` header or labels exist) or by index.
- **File headers** (lines at the top starting with `#key:value`, plus legacy first line `tags:a b c`; metadata.rs:99-202). Keys are case-insensitive: `separator` (name `tab|pipe|semicolon|colon|comma|space` or the literal char; also tolerates a mistakenly exported `#separator:,` row), `html` (`true|false`), `tags` (global tags), `columns` (CSV record of column labels), `notetype` (name or id), `deck` (name or id; unknown name -> create deck), `notetype column`, `deck column`, `tags column`, `guid column` (1-based ints), `match scope` (`notetype` | `notetype + deck`), `if matches` (`update current` | `keep current` | `keep both`). Export writes the same syntax (`#separator:tab`, `#html:true`, `#guid column:1`, ... csv/export.rs:81-122).
- Delimiter auto-detection is naive: first of TAB, PIPE, SEMICOLON, COLON, COMMA that occurs in the first 8 KiB, else SPACE (metadata.rs:`delimiter_from_reader`, "TODO: use smarter heuristic"). `is_html` = any field in the preview contains HTML-ish text. If the first notetype field's column can't be determined -> `ImportError::NoFieldColumn`; empty file -> `EmptyFile`.
- Import semantics (`ForeignData::import`, text/import.rs): per row resolve deck (id/name/column, create if missing; unresolvable -> `missing_deck`), notetype (by name/id/column; unresolvable -> `missing_notetype`), skip empty first field (`empty_first_field`). Duplicate detection: if row has a GUID -> `existing_guids` lookup; else **first-field match** (checksum) within the same notetype (`MatchScope::Notetype`) or notetype+deck. Then by `dupe_resolution`: `UPDATE` (update existing in place; different notetype -> `conflicting`; identical -> `duplicate`; first-field-match updates logged as `first_field_match`), `PRESERVE` (keep existing, log as `duplicate`/`first_field_match`), `DUPLICATE` (always add, except exact GUID dupes). `global_tags` are added to every note; `updated_tags` only applied when an existing note is updated. The chosen dupe resolution and match scope are saved back to collection config (`update_config`, import.rs:54-60). Fields are HTML-escaped when `is_html=false`.
- Encoding: UTF-8 only (BOM stripped, `strip_utf8_bom`); the `csv` crate reader handles quotes/newlines (docs-site/manual/importing/text-files.mdx).
- GUI reference: `qt/aqt/import_export/import_dialog.py` hosts the Svelte page `ts/routes/import-csv` / `import-anki-package` / `import-page` (log display with tabs per category). The UI is TS, so tanki's TUI must re-implement a column-mapping form (doable) - the data model is fully in the proto above.
- Terminal UX: `tanki import notes.tsv --notetype Basic --deck "Spanish" --map Front=1,Back=2 --tags-column 3 --global-tags imported --dupes update|keep|add --match-scope notetype|deck --delimiter tab --html auto|true|false [--dry-run-preview]`. Flow: `GetCsvMetadata` (preview + guessed mapping), apply overrides to the returned `CsvMetadata`, `ImportCsv`. A `--preview` flag that prints the proto `preview` rows and mapping is nearly free. There is **no dry-run for the actual write** (but import is undoable via `Collection::undo`).

### 7.2 Backups

- RPCs: `CreateBackup{backup_folder, force, wait_for_completion} -> Bool`, `AwaitBackupCompletion` (BackendCollectionService, collection.proto:34-42; backend/collection.rs:53-83). `Collection::maybe_backup(&mut self, backup_folder, force) -> Result<Option<JoinHandle<Result<()>>>>` (backup.rs:28-47) is `pub`.
- Semantics (backup.rs): skip if collection unchanged since the last backup of this session (`changed_since_last_backup` compares `mod`, timestamps.rs:41-48) or, unless `force`, if any file in the folder was **created** within `minimum_interval_mins` (default 30) (`has_recent_backup`, uses file *creation* time, not name). Then `checkpoint()` the WAL, read the DB file (skipping SQLite's locked byte range), update the last-backup stamp, and spawn a thread that writes `backup-%Y-%m-%d-%H.%M.%S.colpkg` (a no-media, latest-format colpkg, `export_colpkg_from_data`) and thins old backups. Backups are always created from the *current schema (18)*; "Backups created with 2.1.50 will not be importable into older Anki versions" (docs).
- Retention: `Preferences.BackupLimits{daily, weekly, monthly, minimum_interval_mins}` (config.proto:138-143), stored in collection config key `backups`, defaults **12 daily, 10 weekly, 9 monthly, 30 min** (config/mod.rs:286-296). Algorithm (`BackupFilter`, backup.rs:157-250): keep everything from today and yesterday; then newest-first keep one per day until `daily` exhausted, then one per ISO-ish week (`(day-1)/7`), then one per month; everything else is deleted. Read/modify via `GetPreferences`/`SetPreferences` (`Preferences.backups`) - accessible (`Collection::get_preferences/set_preferences`, preferences.rs:18-27).
- When aqt creates backups: every 5 min timer `on_periodic_backup_timer` -> `create_backup(force=False)`; on profile close (`force=False`, only if quick_check OK and not restoring, not dev mode, main.py:722-737); forced: before full download, Check Database, colpkg import (main.py:1579-1587). Manual: File > Create Backup (`force=True`; "backup unchanged" tooltip if nothing changed). `profileConf.numBackups=50` is a legacy dead key.
- Restore: close collection, `import_collection_package(backup_path)` (= colpkg import, 5.3), reopen. UI: "Open Backup" in profile picker/File menu with a file dialog filtered `*.colpkg` in `profile/backups` (main.py:446-478).
- **tanki:** `tanki backup [--force]`, `tanki backup list`, `tanki restore FILE`. In the TUI run the 5-minute periodic check in-process. **Must** call `await_backup_completion` at exit (section 0.3). Because backups live in the same folder as desktop Anki's, thinning applies across both programs' backups (same naming/limits) - consistent by design.

### 7.3 Empty Cards

- `CardRenderingService::GetEmptyCards(Empty) -> EmptyCardsReport{ string report, repeated NoteWithEmptyCards{note_id, repeated card_ids, bool will_delete_note} }` (card_rendering.proto:17,84-92; impl card_rendering/service.rs:69-80, notetype/emptycards.rs). `will_delete_note = (empty.len() == current_count)` i.e. *all* of the note's cards are empty. `report` contains `[anki:nid:<id>]` markers that the dialog turns into links (qt/aqt/emptycards.py:56-64).
- Deletion is Python logic: collect card ids; if "keep notes with no valid cards" is ticked and `will_delete_note`, **leave the first card** (`card_ids[1:]`), else all; then `RemoveCards{card_ids}` -> `remove_cards_and_orphaned_notes` (emptycards.py:109-125; card/service.rs:48-61) which deletes cards and notes that end up cardless, undoable (`Op::EmptyCards`). Trivially re-implemented.
- **tanki:** `tanki empty-cards [--delete] [--keep-notes]` (default prints report, `--delete` performs it).

See 2.2: `vacuum; analyze` every 14 days in aqt (`lastOptimize` in prefs). tanki: do it inside Check Database or on `tanki optimize`; do not store the timestamp in prefs21.db (use tanki config).

### 7.6 Tools > Add-ons data

Python-only (`qt/aqt/addons.py`). `addons21/<dir>/` + `meta.json` (`name`, `mod`, `disabled`, `conflicts`, `min_point_version`, `max_point_version`, `branch_index`, `human_version`, `update_enabled`, `homepage`, `config`; addons.py:150-159,718). Expect user-visible differences when add-ons altered the collection (add-ons store data in collection config or note fields, which rslib round-trips unchanged).

### 7.7 AnkiHub, AnkiWeb update check, GitHub update RPCs

- `BackendAnkiHubService { AnkihubLogin{id,password} -> {token}, AnkihubLogout{token} }` (ankihub.proto; rslib/src/ankihub/login.rs: POST to AnkiHub's login endpoint; `id` containing `@` is sent as `email`, else `username`). aqt stores `thirdPartyAnkiHubToken`/`...Username` in the profile and then **installs the AnkiHub add-on** (`qt/aqt/ankihub.py`, `install_ankihub_addon`). The token is only consumed by that third-party add-on; core Anki does not sync decks with AnkiHub. **Skip for tanki** (the AnkiHub sync protocol itself is closed/third-party).
- `BackendAnkiwebService::CheckForUpdate{version, buildhash, os, install_id, last_message_id} -> {optional new_version, current_time, optional message, last_message_id}` -> `https://ankiweb.net/svc/desktop/check-for-update` (ankiweb.proto). aqt shows server messages and "new version" prompts and warns on clock skew > 300 s (qt/aqt/update.py:15-70). **tanki should not call it** (it would identify itself as Anki; privacy: sends an install id) unless it has its own update channel. Do not copy the `id` field from Anki's prefs.
- `BackendGithubService { GetLatestRelease{include_prerelease} -> GithubRelease{tag_name, filename, url, checksum}, DownloadRelease(GithubRelease) -> String }` (github.proto; backend/github.rs): used by the Anki *launcher* self-updater (`rslib/src/updates.rs`, platform suffixes for installers). Irrelevant to tanki.

## 10. Concrete implementation checklist for the data layer

1. `ProfileStore`: resolve base (flag > `ANKI_BASE` > OS default) ; enumerate profiles (read-only prefs21.db, fallback to directory scan); `collection_path = base/<name>/collection.anki2`; `media = base/<name>/collection.media`; `media_db = base/<name>/collection.media.db2`; `backups = base/<name>/backups`.
2. `Session::open(profile)`: `Backend::new(I18n, server=false)`; `open_collection(OpenCollectionRequest{...})`; map `DbErrorKind::{Locked, FileTooNew, FileTooOld, Corrupt}`; set `PLATFORM` env deliberately before first sync.
3. `Session::close()`: `await_backup_completion`; optional backup (`create_backup(force=false, wait=false)` after quick-check like aqt `_unloadCollection`); `close_collection(downgrade=false)` (also aborts media sync).
4. `Sync` module: auth from tanki config (or imported once from Anki); `sync_login`; `sync_collection{auth, sync_media}`; handle `new_endpoint`, `server_message`, `required`; background poller for `latest_progress`; abort on Ctrl-C (`abort_sync` + `set_wants_abort`); media poller until inactive; clock/auth/sanity errors mapped from `SyncErrorKind` with `SyncError::message`.
5. `SafetyNet`: `pre_destructive_backup()` used by full download, restore, check-db, import-with-scheduling; schema-change guard.
6. `Media` module: add (path/url/bytes), check/trash, LaTeX renderer.
7. `ImportExport` module: thin wrappers + `ImportResponse.log` pretty-printer (+ `--json` machine output).
8. Config keys tanki should persist itself: sync endpoint/auth/auto flags/media flag/periodic minutes/timeout, CA cert, UI prefs, last profile.

## 11. Risks, surprises, and things not verified

**Data-safety risks of sharing a profile with Anki desktop**
1. SQLite exclusive lock protects the collection file itself **[verified]** - second opener fails fast. Good. But it does **not** protect `collection.media*`, `prefs21.db`, or atomic-rename-based restores (colpkg import and full sync download rename over `collection.anki2` regardless of who holds it).
2. Never write prefs21.db (Anki overwrites whole rows on save; pickles contain enum class references that naive rewriters destroy -> Anki resets the profile to defaults).
3. Any raw SQL on `decks/notetypes/tags/fields/templates/deck_config` outside rslib fails or corrupts due to the `unicase` collation **[verified error]**.
4. Mutating notetype/deck-config operations silently set the schema-modified flag; rslib has no confirm step (Python does). A TUI that forgets the guard can force the user's next sync into a destructive one-way choice.
5. `Check Media` rewrites note HTML (rename refs, extract inline images) with no dry run.
6. Pre-upgrade: opening a schema-11 collection upgrades it to 18 permanently (older Anki < 2.1.50 can then not open it). No automatic copy is made.
7. Short-lived CLI processes must `await_backup_completion` or truncate a backup mid-write; media sync must finish before closing or it is aborted (by design).
8. Version skew between tanki's rslib and the user's desktop version (user here runs 25.09.4; the source tree is 26.08.1) is fine at schema level (both 18) but newer rslib may store newer config/card-data fields **[unverified]**; consider pinning tanki to an `anki` crate version and warning when `last_run_version` in prefs21.db is far older.
9. Client identification on sync: default is `anki,26.08.1 (dev),linux`; decide policy (spoofing "Anki" vs honest `tanki`); risk of AnkiWeb ToS/compat friction **[unverified]**.

**Surprises**
- `with_desktop_media_paths()` uses `.mdb`, desktop uses `.media.db2`.
- Trash is `<profile>/media.trash/` (sibling).
- New media files are lower-cased on add.
- Backup "recent" test uses file *creation* time (`created()`), which some filesystems (and tmpfs/older Linux kernels without statx) do not provide - if unsupported `.ok()` filters it out so backups are never throttled **[unverified on this platform]**.
- `hostNum` is vestigial; `currentSyncUrl` is the real redirect cache.
- `SetCustomCertificate` is implemented but unused by Anki's own UI.
- `AddMediaFromUrl` panics (`unwrap`) when no collection is open.
- aqt sets `restoring_backup` to suppress auto-sync/backup after restore (in-memory only); a CLI restore should likewise skip auto-sync for that run.
- Only one progress slot exists: do not run import/export/check/sync concurrently from tanki and expect separate bars.
- Legacy importers (supermemo/pauker/etc.) are gone from this release; Mnemosyne is the only Python importer left.
- A real install had `currentSyncUrl` populated, no `customSyncUrl`, `hostNum` set, `autoSync` and `syncMedia` true, `numBackups` legacy key, geometry blobs suffixed `6.9` (Qt version) - consistent with the analysis above.

**Not verified (could not or did not test)**
- `serde-pickle` behaviour on the REDUCE/enum and `sip` cases (crate not available offline here).
- Whether AnkiWeb issues the same hkey for repeated logins, and whether non-"anki" client strings are rejected.
- Runtime failure mode of an `anki` build without `rustls`/`native-tls`.
- Stale `-wal` + atomic-rename hazard in colpkg import (theory only).
- `ankiweb.net/shared/downloadDeck/...` anonymous download behaviour.
- Behaviour when tanki's rslib is *older* than the collection's feature set (e.g. new FSRS fields).
- No code was built or run from the Anki tree; Rust signatures were read from source, not compiled. The Python snippets run were in a scratch directory against copies of the user's `prefs21.db` / `collection.anki2` (copies deleted; only key names/types/schema inspected, no secrets or card content recorded).
